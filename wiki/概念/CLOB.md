# CLOB · 中央限价订单簿（Central Limit Order Book）

## 核心直觉：同一张 $1 兑换券的两半
「到期必定值 $1」的兑换券被拆成互补两份 **YES / NO**：
- 事件**发生**：YES = $1，NO = $0；
- 事件**不发生**：YES = $0，NO = $1。

因此 **YES 价格 `p` + NO 价格 `(1−p)` ≈ 1**。
例：买 YES @0.18 ⇄ 等价卖 NO @0.82（镜像报价）。

## 为什么市场会「自动互补」
- YES/NO 不是两支独立资产，而是**互补结果**；
- 挂单在另一侧自动生成镜像价（NO = 1 − YES）；
- 若有人挂出「YES + NO < 1」的不平衡报价，系统直接撮合成交（套利消除）；
- 两边合成**同一个订单簿** → 集中流动性、缩小价差、加速价格发现。
- 买齐 YES+NO = 买到「到期必定 $1」的组合，故两者价格必须互补、合计 ≈ 1。

## 对比
CLOB（订单簿撮合，价差/深度由挂单决定）vs AMM（自动做市商，恒定函数定价）。See-X/Kairos 走 CLOB 路线，配合 [[做市与流动性]] 解决早期深度。

## 在 Kairos 的应用
Kairos 预测市场的撮合与定价层默认采用 CLOB；新手 UI 把「买 YES/卖 NO」翻译成直觉化的「看涨/看跌 + 概率%」。
